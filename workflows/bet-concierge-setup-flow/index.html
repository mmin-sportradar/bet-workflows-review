ADDITIONAL STEPS · DEEPER INTEGRATION · OPTIONAL

Optional integration paths Review Basic, Full, and Premium integration options and their client eligibility.

1 · SALES REPS · PRODUCT OFFER

Product Offer

Create a new opportunity or amend existing opportunity with a Quote where product Bet Concierge is selected. Make a Service Administration Request.

Basic integration

Chat only – no odds.

Can be offered to all clients.

Full integration

Odds – single markets.

Can be offered to all clients.

Premium integration

Odds – multiple markets.

Can be offered only to clients that have Custom Bet (Custom Bet API – on top of UOF).

2 · SALES REPS · SERVICE REQUEST

Service Request

In the comment box provide:

Mandatory

  • IPs / Domains that should be whitelisted;
  • Store ID if available (for existing BET clients on Widget type solutions);
  • Active Bookmaker ID is mandatory for JWT authentication. If new BID needs to be generated please mark it accordingly;
  • Type of integration – Basic, Full or Premium integration.

JIRA TICKET will be automatically created for the Bet Integration team. In case mandatory requests are not specified, Bet Integration team will request it via Jira ticket.

Signing the amendment

To grant clients Bet Concierge (trial or post-sale request), they need to agree with necessary clauses and DPA. For post-sale requests, the clauses are to be included in MSA. For pre-sale trial, please find amendment including all the clauses here.

Signed Amendment needs to be attached to Jira.

3 · BETI · SETUP

Setup

BETI team will activate selected product in Store, request generation of new BID (following the process of requesting BID for Translations) if needed and update the Jira by:

  • Adding INTEGRATION INSTRUCTIONS PDF file;
  • Adding the link to the documentation for creating JWT token.

BETI team adds the Sales director and SSS of client in the Slack channel “#bet-concierge-alerts” for prompt monitoring. Messages of 80% and 100% prompt consumption will be sent to this channel.

BETI workstream

Create a new Initiative / Epic in the BETI Jira Project (detailed instructions here).

After the Epic is created, the automation will create ticket for BETI Client Integration Prerequisites (setup purposes).

4 · SALES REPS · COMMUNICATION

Communication

Sales contacts the client via e-mail and includes BET Integration team, Blaž Bezek and Uroš Prah in the e-mail chain. E-mail sent to the client includes:

  • A link to technical documentation;
  • Request for client to provide the Public RSA key (created in the process of obtaining JWT token).

Shared technical workspace

Establish a shared Slack channel including the Sales Director, SSS, Nina Krmavnar, and Ilija Tomić for Adapter creation for the initial setup phase.

Sales director or SSS invite members from client’s team to kick-off the setup process. Requests to add external people to Slack channels can be made here.

Both SR and client’s technical team will be included in the Channel to monitor the progress of technical development. BETI team and engineering team will delegate the created tasks and monitor the progress visible on Jira Board.

5 · BETI · CONFIGURATION

Configuration

BET Integration team applies the provided Public RSA key to correct account, adds the corresponding Bookmaker ID and follows up with the client regarding the other configurable parameters:

  • Number of prompts in selected time frame (default 10.000 prompts monthly);
  • Number of prompts per end user (default 100 prompts daily);
  • Number of prompts per user group (e.g. 100 prompts daily for regular users, unlimited prompts for VIP users);
  • Concurred (number of prompts in selected time frame (default 60 prompts in 60 seconds).

6 · SALES REPS · MONITORING AND INVOICING

Monitoring and Invoicing

The team follows up with the client until the client has gone live.

Limit consumption is monitored through Slack channel “#bet-concierge-alerts”. When the message of 80% and 100% quota consumption is received, BET team or Sales inform the client via e-mail.

The service can be set up to either automatically stop once the purchased prompt quota is reached, or to continue operating, charging the client for each additional prompt at the agreed rate.

SSS handles invoicing for the fixed fee, while the BET product team tracks usage and informs the SSS if invoicing for extra prompts becomes necessary. Please find invoicing details HERE.
