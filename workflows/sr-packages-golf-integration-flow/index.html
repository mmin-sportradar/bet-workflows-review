LMT Golf BET Integration

Premium Golf Service Essential and Advanced

Responsibilities:
Package scope: Essential activates regular LMT Golf in Store, with no cross-team work. Advanced activates LMT + LMT Premium + LCO via LMT — IMGA for the operator, AV for LCO via LMT.
SPORTRADAR
8 September 2026

BET INTEGRATION TEAM

Identify package and client type

When a cloned ticket is assigned to BETI from Customer Support, check the contracted package and whether the client is new or an existing IMG migration.

  1. Confirm whether Salesforce requested Premium Golf Service Essential or Premium Golf Service Advanced.
  2. Confirm whether the client is new or an existing IMG / IMT Event Centre migration. Check the list of existing IMT clients.
  3. An operator name in the IMG repository does not mean they are still an IMG client — some names remain from a previous IMG relationship.

Essential

Activate regular LMT Golf only. No cross-team coordination; the work is self-contained in Store.

Advanced

Activate LMT + LMT Premium + LCO via LMT. IMGA confirms the operator (Slack). AV handles LCO via LMT.

IMGA TEAM · ADVANCED

Confirm the operator name

For Premium Golf Service Advanced, confirm or create the operator name via Slack.

BETI checks the IMGA repository and enters the confirmed name in Store. Essential does not need this coordination.

BET INTEGRATION TEAM

In-Store activation

  1. Check the IMGA repository for an existing operator name, or create one if the client is new.
  2. For Advanced, use the operator IMGA confirmed on Slack.
  3. Enter the operator name into the imgaOperator field in Store.
  4. Activate the LMT Golf widget depending on the package.

BET INTEGRATION TEAM

Share docs by client type

New clients

Share the standard API Hub Golf LMT documentation and the Golf LMT demo pages in the Jira ticket.

Existing IMG Event Centre migrations

If they want to keep their existing layout and styling, send the Migration Integration Guide. That guide is internal — do not share it with brand-new clients.

Remind the client of the legacy sunset date: 30 November 2026.

BET INTEGRATION TEAM

Check AV scope

LMT only

Add handover details and close the ticket.

LCO via LMT

Stay on this flow. AV provides the Bookmaker ID and later the JWT / RSA handoff; BETI connects the order and applies the key.

AV TEAM · LCO VIA LMT

Provide the AV Bookmaker ID

BETI will have configured the LMT widget in Store and asked on Jira:

@av-integration, LMT widget has been configured in Store. Could you please provide the AV Bookmaker ID for this client so we can connect it to the order?

Reply on the Jira ticket with the AV Bookmaker ID.

BET INTEGRATION TEAM · LCO VIA LMT

Connect the order

Link the AV Bookmaker ID to the order in Store. Then tag AV:

@av-integration, Store configuration complete. AV Bookmaker ID [XXXXX] is now linked to Order [YYYYY]. Please share the JWT authentication documentation with the client and request their Public RSA Key.

AV TEAM · LCO VIA LMT

Share JWT docs and request the RSA key

Share the JWT authentication documentation with the client and request their Public RSA Key.

Post the client’s Public RSA Key on the Jira ticket for BETI to apply in Store.

BET INTEGRATION TEAM · LCO VIA LMT

Apply the RSA key

Once AV provides the client’s Public RSA Key in Jira, apply it to the client’s account in Store.

If the client already has an active Public RSA Key configured for other existing LCO services, re-upload is not needed.

Post final confirmation:

Public RSA Key has been applied. LMT is ready for embedded LCO.
